# ADR 0007: piloto de avaliações de usuários do Steam

**Status:** implementado em 2026-09-24 como coleta manual limitada. Ainda não há medição de precisão da extração em reviews reais.

- `steam_reviews` associa um App ID a um produto do tenant. A API aceita ID decimal ou URL HTTPS de produto em `store.steampowered.com`, normaliza para `https://store.steampowered.com/app/{id}/` e aplica RBAC e RLS. O worker reconstrói a chamada exclusivamente para `https://store.steampowered.com/appreviews/{id}`. Um endpoint HTTP local substituto existe somente em `MARKETRIFT_TEST_MODE=1` para E2E; não é entrada do usuário. O job BullMQ v1 leva somente versão, IDs e chave de idempotência. O worker verifica no banco fonte, produto, execução e tenant antes de consultar a rede.
- Cada execução manual permite 1–3 páginas e 1–50 reviews; a interface sugere uma página e cinco reviews. A primeira usa `filter=recent`; as seguintes usam `filter=updated` com sobreposição de 24 horas em relação ao maior `timestamp_updated` visto. A API Steam fornece paginação por `cursor`. O worker interrompe em limite de itens/páginas, página vazia ou janela temporal já coberta, e registra se a varredura terminou. Uma execução limitada **não é backfill completo**. Se chegarem mais atualizações do que o limite permite, `scan_complete=false` exige ampliar os limites e revisar a cobertura; a sobreposição não garante capturar um volume arbitrário de atualizações. Não há agendamento nem coleta em massa nesta etapa.
- O conector interpreta 404/410, 403, 429, timeout, 5xx e resposta inválida com códigos de erro separados; 5xx e erros de rede fazem até três tentativas com espera curta. `Retry-After`, quando presente, define o próximo horário permitido. O cliente não segue redirecionamentos. O lote só grava documentos depois de receber todas as páginas permitidas sem erro; falhas não deixam documentos parciais. O estado da execução fica em `source_runs`.
- `recommendationid` é o ID externo estável. A chave única `(tenant_id, source_id, external_key)` evita duplicatas; mudança no texto/metadata atualiza o mesmo documento. `steam_review` mantém texto original, App ID, idioma, `voted_up`, criação e atualização informadas pela fonte e `synthetic=false`. Campos de autor, incluindo SteamID e histórico de jogos, são descartados. O endpoint documentado não fornece permalink individual verificável sem dados de autor; o link apresentado leva à seção de avaliações do produto e é identificado como tal. Não afirmamos que ele abre a review exata.
- `voted_up` é a recomendação positiva/negativa no Steam, não uma classificação de dor. Issues GitHub, reviews Steam e avaliações CSV têm tipos distintos. A mesma fonte vinculada a dois produtos gera documentos separados por fonte; a UI avisa que o mesmo relato não deve ser somado duas vezes numa comparação futura.
- A coleta **não** enfileira análise paga. O usuário com papel owner, admin ou analyst pode escolher uma review e pedir análise de **um documento**. O extrator existente aceita vários problemas e exige trecho literal de evidência. Uma review positiva pode resultar em zero problemas. Se o texto de origem mudar, a análise antiga fica pendente/oculta e uma nova execução exige outra ação. A taxonomia atual foi feita para problemas de produtos de software (`support`, `price`, `billing`, `performance`, `usability`, `features`); ela pode não cobrir gameplay, conteúdo e outras dimensões de jogos. Zero problemas classificados não demonstra ausência de reclamação. Não usamos classificações Steam em gráficos, alertas ou recomendações.
- Steam é um piloto técnico para produtos distribuídos nessa plataforma e não representa SaaS B2B em geral nem todos os consumidores de um jogo. A documentação da API descreve filtros e campos; não concede, por si só, autorização irrestrita de redistribuição ou uso comercial do conteúdo. Antes de operar um SaaS público, revisar as condições aplicáveis e a retenção/uso do conteúdo com a fonte e orientação jurídica. Dados de teste reais não entram no conjunto de avaliação automaticamente. Para avaliar qualidade, obter uma amostra legítima, rotular presença de problema, categorias, gravidade e evidência **antes** de ver previsões, então rodar o avaliador existente com orçamento explícito; adaptar a taxonomia a jogos se os rótulos mostrarem lacunas.

Referências oficiais: [Steam User Reviews API](https://partner.steamgames.com/doc/store/getreviews) e [Steam Subscriber Agreement](https://store.steampowered.com/subscriber_agreement/).
