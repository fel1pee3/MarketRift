# ADR 0006: coleta manual de Issues públicas do GitHub

**Status:** implementado em 2026-09-24.

- `github_issues` é uma fonte associada a produto ou concorrente. O cadastro aceita somente `owner/repo` ou URL simples de `https://github.com/owner/repo`; a API grava a forma canônica. O worker reconstrói chamadas apenas para `https://api.github.com/repos/{owner}/{repo}/issues`, não segue redirecionamentos e rejeita URLs de Issue ou paginação fora dos hosts e caminhos esperados. Não há scraping, token GitHub nem coleta de repositório privado.
- `owner` ou `admin` cadastra a fonte; `owner`, `admin` ou `analyst` solicita coleta; `viewer` apenas lê. A API confirma membership por operação, usa transação com `app.tenant_id` e RLS. O job contém só versão, IDs e chave de idempotência. O worker valida o contrato e confirma no banco que run e fonte pertencem ao tenant.
- Cada execução manual limita 1–3 páginas e 1–50 Issues. O worker usa `state=all`, ordenação por atualização, `since` e sobreposição de um minuto nas execuções incrementais; segue apenas o sinal `rel="next"` da API. Uma primeira execução limitada busca as Issues mais recentes e **não faz backfill histórico**. Pull Requests são ignorados. Uma falha invalida o lote e não grava documentos parciais.
- `source_runs` guarda estado, cursor, limites, contagens, erro e prazo de retry; `sources.last_checked_at` marca sucesso. A API impede execuções simultâneas e pode reenfileirar uma execução pendente. Se o worker parar, uma nova solicitação pode encerrar como falha uma execução marcada `running` há mais de dez minutos. 404, 403, 429, timeout e 5xx possuem tratamento separado; `Retry-After` e `x-ratelimit-reset` suspendem nova coleta da fonte até o prazo. Não se contornam bloqueios.
- O ID externo é o ID estável da Issue. Documentos guardam URL original validada, repositório, título, corpo, datas e estado, sem autor, email ou assignees. A chave única `(tenant_id, source_id, external_key)` impede duplicatas; uma Issue alterada atualiza o documento. A migração 006 adiciona metadados sem mudar o fluxo de avaliações.
- Uma Issue é manifestação pública em um projeto, possivelmente de mantenedor, colaborador, bot ou usuário; **não é review nem reclamação comprovada de cliente** e não representa a opinião do mercado. O tipo `github_issue` não entra na fila de extração de avaliações, não cria `document_analyses` e não entra nas métricas de avaliações reais. O contrato e prompt `review-issues-v1` foram escritos para avaliações de clientes; aplicá-los a Issues confundiria relatos técnicos e pedidos de funcionalidades com sentimento de clientes. Não há ação paga de análise de Issues nesta entrega; uma futura análise opt-in exigirá prompt, schema, taxonomia, limite e avaliação próprios.
- A API pública sem autenticação permite 60 requisições por hora compartilhadas por IP segundo a documentação atual do GitHub. A coleta é manual e pequena nesta fatia; agendamento, GitHub App, webhooks e backfill histórico requerem desenho posterior. Para avaliar qualidade, selecione manualmente uma amostra diversa de Issues coletadas, registre URL/data e rótulos humanos **antes** de ver previsões, adapte um conjunto versionado específico para Issues e meça erros. Isso não substitui a avaliação em avaliações de clientes reais.
